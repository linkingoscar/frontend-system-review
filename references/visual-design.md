# 视觉与设计系统评审指南

把设计质量判断建立在产品定位、任务清晰度、一致性和真实界面证据上。不要把个人偏好伪装成通用规则，也不要默认所有产品都应采用同一种“高级感”风格。

## 1. 先建立设计意图

评审前先回答：

- 产品为谁服务，用户此刻要完成什么？
- 品牌需要传达可信、效率、活力、温度、专业、娱乐还是其他气质？
- 这是内容型、交易型、工具型、数据密集型还是品牌表达型界面？
- 当前设计约束来自品牌、已有设计系统、平台惯例还是实现成本？
- 哪一个视觉或交互决定应成为页面的 signature，其他部分如何克制？

若品牌简报缺失，可以描述当前视觉语言及其影响，但不要擅自把界面改判为某种流行风格。对美学意见标注为“客观缺陷”“与目标不匹配”或“可选偏好”。

遵循以下优先级：

```text
任务清晰 > 装饰美观
可访问与可操作 > 视觉效果
一致且有意图 > 追逐新颖
真实内容 > 占位内容
长期可维护 > 一次性惊艳
```

## 2. 十个评审维度

### 2.1 品牌与受众匹配

- 检查色彩、排版、影像、语气和动效是否共同表达同一种品牌性格。
- 检查界面是否只是通用模板，或是否存在与产品内容相关的独特设计决定。
- 检查大胆元素是否集中在少数高价值位置，而不是所有区域同时抢夺注意力。
- 检查信任敏感场景避免噱头、虚假紧迫、廉价素材和夸张庆祝。

### 2.2 信息层级

- 检查用户第一眼能否识别页面目的、当前状态、主操作和下一步。
- 检查每个视图是否只有一个主要强调点，次要动作是否适当降级。
- 检查标题、正文、元数据、帮助和状态信息能否通过字号、字重、位置与间距区分。
- 不要依靠增加颜色和卡片数量来制造层级。

### 2.3 布局与网格

- 检查容器、列、gutter、对齐线和内容宽度是否稳定。
- 检查组件内部 padding、跨 section 节奏和移动端边距是否来自一致 scale。
- 检查阅读内容维持舒适行长，数据密集页面在密度与扫描效率间平衡。
- 检查视觉居中与数学居中差异，图标、文字和控件基线是否协调。

### 2.4 留白与密度

- 检查留白是否帮助分组、顺序和重点，而非只是“空间大”。
- 检查相近关系使用相近间距、不同层级使用明显不同间距。
- 检查桌面与移动端重新编排密度，而非等比例压缩。
- 对后台和专业工具允许高密度，但保证分组、对齐和操作目标清晰。

### 2.5 排版

- 检查字体选择与品牌、语言和内容场景匹配；通常控制字体家族和字重数量。
- 检查 display、H1–H3、body、small、caption 形成可辨层级。
- 检查正文行高、行长、中英文混排、数字对齐和断行。
- 检查字体加载、fallback 和不同平台渲染不会破坏布局。
- 不要把 Inter、衬线标题或超大字作为无条件“高级感”配方。

### 2.6 色彩、表面与质感

- 检查中性色、品牌色、状态色和强调色有清晰语义与比例。
- 检查 light/dark 中的表面层级、边框、阴影和状态对比独立成立。
- 检查质感来自细节一致性，而非重阴影、过度模糊、玻璃拟态或大面积渐变。
- 检查错误、警告、成功和选择状态不只依靠颜色。
- 若使用纹理、渐变或强色，判断它是否服务品牌与内容，而不是一律禁止。

### 2.7 图标、图片与插画

- 检查图标库、stroke、尺寸和视觉重量一致；图标不替代关键文案。
- 检查正式产品是否把 emoji 当作缺乏意图的默认图标。
- 检查图片比例、裁切、光线、色调、分辨率和内容真实性。
- 检查插画有品牌语言和信息作用，避免无意义漂浮图形与通用 AI 素材感。
- 同时检查 alt、尺寸占位、格式和加载策略。

### 2.8 组件与状态完整性

- 检查 primary、secondary、ghost、danger、disabled 等操作层级明确。
- 检查表单 label、helper、error、focus、disabled 和提交状态完整。
- 检查 card、table、navigation、dialog、toast、skeleton、empty 和 error 状态有一致规则。
- 检查 loading 不引发布局抖动，empty/error 提供恢复动作。
- 检查组件不是“每个区域一个白卡片”，也不是所有元素使用相同大圆角。

### 2.9 动效与反馈

- 检查动效解释状态、层级或空间变化，而非只为吸引注意。
- 优先短促、可中断的 transform/opacity 动效；避免 `transition: all`。
- 检查 press、loading、导航、弹层和异步操作提供及时反馈。
- 检查 reduced motion 下信息仍完整，页面级动画不拖慢 LCP 或交互。
- 对时长和缓动以现有 motion token 为准；没有 token 时再建议建立一套小规模系统。

### 2.10 文案与信任

- 检查按钮和标题使用具体动作与结果，避免“提交”“点击这里”等模糊词。
- 检查错误说明原因、影响与恢复路径，不责怪用户。
- 检查真实内容下的长度、数字和空状态，不只在理想占位数据下好看。
- 检查营销承诺、紧迫感、社会证明和默认选项不存在欺骗性模式。

## 3. 设计系统与组件细节

### Token

- 使用语义 token 表达 background、surface、text、border、accent 和 state，而非只给原始色阶。
- 建立有限的 spacing、radius、shadow、type 和 motion scale；允许少量有意例外并记录原因。
- 避免在报告中凭空发明整套色值。只有用户要求方案且能看到品牌上下文时才给 token 示例。

### Button 与控件

- 保证层级、点击目标、文案、图标位置、focus-visible、loading 稳定和 disabled 行为一致。
- 不把 disabled 只做成低透明度；同时表达不可操作状态并阻止交互。
- 让危险操作与普通主操作有语义差异，并提供确认或撤销。

### Form

- 保持 label 可见，错误靠近字段，帮助文本和必填语义明确。
- 保证输入、select、checkbox、radio 和日期组件在不同状态下视觉与行为一致。
- 不用 toast 代替字段错误，不让 placeholder 承担全部说明。

### Table 与数据界面

- 让数字对齐、列层级、状态 badge、排序、选择和批量操作清晰。
- 降低无意义网格线与按钮噪音；截断内容提供可发现的查看方式。
- 为移动端选择重排、横向浏览、摘要卡片或关键列保留策略。

### Dialog、Toast 与异步状态

- 保证 dialog 层级、标题、关闭、焦点、滚动和主操作位置可预测。
- 保证 toast 位置稳定、可感知、可关闭且不遮挡任务。
- 让 skeleton 与真实内容几何接近；长任务显示阶段或进度，而非无限 spinner。

## 4. 视觉反模式

将以下内容作为调查线索，不要机械判错：

- 默认紫蓝渐变、过度玻璃拟态、霓虹色、假 3D、无意义抽象插画；
- 所有内容卡片化、所有元素超大圆角、阴影过重、边框与半透明层过多；
- 字号层级不清、间距随机、多个主色竞争、图标风格混用；
- 只有 hover 没有 focus，暗色模式直接反色，低对比灰字；
- 空状态无引导、错误无恢复、loading 抖动、移动端只是桌面缩小；
- lorem ipsum、夸张感叹号、虚假紧迫和与产品无关的 AI 文案。

只有当它损害品牌匹配、理解、信任、可访问性、一致性或任务效率时，才形成 finding。

## 5. 截图与报告方法

- 用相同内容、视口、主题和滚动位置比较 before/after 或设计参考。
- 记录路由、视口、状态与截图时间；不要只截取无法定位的局部。
- 先写客观缺陷，再写与设计目标的偏差，最后才写可选偏好。
- 对每个问题说明“看到了什么 → 为什么影响任务或品牌 → 如何最小修复 → 如何复检”。
- 避免只写“更高级”“更现代”“多留白”。把建议落实到层级、对齐、token、组件状态或内容策略。
