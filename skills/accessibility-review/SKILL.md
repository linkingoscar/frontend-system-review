# Accessibility Review

默认目标为 WCAG 2.2 AA 和真实任务完成；项目有更严格法规或范围时以项目要求为准。记录采用的标准版本、核对日期和权威来源。

## 工作流

1. 选择代表性页面、角色、任务和状态，包括错误、弹窗、动态更新与会话边界。
2. 只用键盘完成关键任务，检查跳转链接、顺序、可见焦点、陷阱、恢复位置和快捷键冲突。
3. 检查 landmark、heading、label、name/role/value、按钮与链接语义、语言和页面标题。
4. 检查表单说明、必填、错误关联、汇总、实时校验和提交后焦点。
5. 检查对比度、200%/400% 缩放、文本间距、重排、触控目标、动画和高对比模式。
6. 使用至少一种读屏流程验证关键任务；记录浏览器、读屏器和操作序列。
7. 运行 axe 等自动工具补充线索，对 incomplete 和人工规则逐项复核。

## 纪律

- 自动扫描“0 violations”不等于通过；未运行或未覆盖不能写成通过。
- 从源码看到 ARIA 不代表运行时语义正确；从截图看不到读屏顺序。
- 严重度按任务阻断、影响用户范围、是否存在替代路径和法规范围校准。
- 对比度采样遇到图片、渐变、透明叠层、伪元素或动态状态时必须人工复核。

## 输出

每条 finding 指明适用准则、页面/状态、用户群、复现步骤、实际与期望结果、证据、修复和复测步骤。另附页面×任务×输入方式覆盖矩阵和未覆盖项。被总控调用时将阻断型问题交由总控纳入上线门禁。
