# Frontend Release Review

判断目标不是“CI 是绿色”，而是同一份可追踪制品能否安全推广、观测、回滚和恢复。

## 工作流

1. 识别源码版本、锁文件、运行时版本、构建命令、环境输入、生成物和部署目标。
2. 验证本地与 CI 构建是否使用锁定依赖和相同契约，制品是否带版本、来源、哈希与 SBOM/来源证明。
3. 检查 typecheck、lint、test、build、安全和运行时 smoke 门禁是否覆盖关键失败模式，是否存在可审计例外。
4. 检查环境变量、秘密、source map、CSP、缓存、CDN、迁移与前后端兼容窗口。
5. 检查灰度、feature flag、回滚、向前修复、数据兼容和灾难恢复步骤是否被演练。
6. 检查错误、性能、关键任务、版本和业务指标能否关联到发布，并有 owner、阈值、告警和停止条件。
7. 检查发布后 smoke、合成监控、RUM 与人工抽查是否验证真实用户路径。

## 纪律

- README 中的命令不算通过证据；运行并保存退出码与完整失败原因。
- 能重新构建不等于能回滚；回滚必须处理缓存、配置、API/数据兼容和不可逆变更。
- 没有项目确认的预算，不擅自把主观分数或所有 P2 设为合并阻断。
- 第三方 Action、包和脚本按权限、固定版本、来源和更新责任评审。

## 输出

给出发布链路摘要、阻断项、门禁矩阵、制品可追踪性、回滚/RTO 风险、观测缺口和发布后验证清单。每条 finding 带证据、owner 建议、修复和演练方式。被总控调用时提交发布候选和建议 verdict，由总控结合其他专项形成最终结论。
