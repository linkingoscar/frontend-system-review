# Web 运行时质量清单

用于 URL、可启动应用、截图、可访问性、性能、SEO、响应式和交互审查。源码只能证明实现倾向；浏览器中的真实 DOM、行为和测量才是运行时证据。

## 目录

1. 路由与任务矩阵
2. 可访问性
3. 表单与交互
4. 响应式与布局稳定性
5. 性能与 Core Web Vitals
6. SEO 与可发现性
7. 内容、国际化与主题
8. 验证协议

## 1. 路由与任务矩阵

先建立小而有代表性的矩阵：

- 公开入口或首页；
- 一个内容详情或核心业务页面；
- 一个高交互页面；
- 登录、表单、交易或其他关键任务；
- empty、error、loading、无权限或 not-found 状态；
- 共享 header、navigation、dialog、table、card 等组件家族。

对每个路由记录：角色、任务、数据状态、视口、主题和验证方式。深度审计至少保留桌面与移动基线截图，并在修复后用相同状态复拍。

## 2. 可访问性

以 WCAG 2.2 AA 和真实任务完成为默认目标；如果项目有其他合规范围，以项目要求为准。自动扫描只能发现一部分问题。

### 结构与语义

- 检查语言、title、landmark、skip link、heading 层级和唯一主标题。
- 优先原生 `button`、`a`、`input`、`dialog` 等语义；不要用 ARIA 修复错误元素选择。
- 检查可访问名称、description、role、state 和 value 是否与视觉信息一致。
- 检查 icon-only 控件、装饰图标、图片 alt、图表和复杂可视内容的替代信息。
- 检查动态状态是否使用合适的 live region，避免重复或过度播报。

### 键盘与焦点

- 仅用键盘完成关键任务，检查顺序、可见焦点、快捷键冲突和无焦点陷阱。
- 检查 dialog、drawer、menu、popover 打开时的初始焦点、循环、Esc 和关闭后焦点恢复。
- 检查粘性 header、cookie banner 或浮层不会遮挡焦点。
- 检查路由切换、错误提交和异步更新后的焦点去向。

### 感知与运动

- 检查文本、图标、边框和焦点指示器对比；不要只凭肉眼估计临界值。
- 检查信息不只依靠颜色、位置、声音或动画表达。
- 检查 200%/400% 缩放、文本放大和窄视口下仍可使用。
- 检查 `prefers-reduced-motion`，避免自动播放、闪烁和无法暂停的内容。
- 检查触控目标大小与间距；对精确阈值引用当前适用标准。

### 工具与人工检查

- 可运行 axe、Lighthouse a11y、eslint 插件或项目工具，但记录版本、URL 和环境。
- 对自动结果去重并确认 DOM 上下文，不要照抄所有工具告警。
- 关键流程补充键盘和至少一次主流读屏走查；没有执行时明确标为未验证。

## 3. 表单与交互

- 检查每个控件有持久可见的 label；placeholder 不替代 label。
- 检查合适的 `type`、`name`、`autocomplete`、`inputmode` 和说明文本。
- 不阻止粘贴；不要无理由禁用缩放或自动聚焦。
- 检查客户端与服务端校验一致，错误靠近字段、可被感知并能聚焦首个错误。
- 检查提交中的重复操作、按钮尺寸稳定、取消、重试和成功反馈。
- 检查未保存更改、破坏性操作的确认或撤销、离线和会话过期恢复。
- 检查 hover、focus-visible、active、disabled、loading、empty、error、success 状态。
- 检查 URL 是否承载应分享、刷新和返回的筛选、分页、tab 或搜索状态。
- 检查 toast 不替代字段错误，也不遮挡关键控件。
- 检查拖拽、hover-only、手势和右键操作都有等价方式。

## 4. 响应式与布局稳定性

- 至少检查 375px 左右移动视口和常见桌面视口；按产品设备分布扩展矩阵。
- 检查横向滚动、裁剪、重叠、不可达内容、固定高度和 sticky/overlay 冲突。
- 检查 safe area、虚拟键盘、浏览器工具栏和方向变化。
- 检查图片、视频、广告、embed、字体和异步内容预留尺寸，避免布局位移。
- 检查表格、图表、导航和工具栏有明确小屏策略，而不是简单整体缩小。
- 检查长文本、长单词、国际化、用户生成内容和动态数字不会破坏布局。
- 检查滚动锁不会造成页面侧移，嵌套滚动区域可发现且可键盘操作。
- 检查 `min-width: 0`、flex/grid 溢出、层叠上下文和 z-index 体系。
- 对视觉问题记录页面、视口、状态、组件和截图，不要仅写“移动端不好看”。

## 5. 性能与 Core Web Vitals

优先真实用户数据，其次可复现的实验室测量，最后才是源码推断。正式交付使用 [standards-baseline.json](standards-baseline.json) 中带复核日期的版本化快照，并运行 `../scripts/check_standards_freshness.py`；快照过期时先核对其中的权威来源，再更新阈值和复核窗口。项目 SLO 优先于通用良好体验阈值，但两者必须明确区分。

常用良好体验参考：LCP 约不高于 2.5s、INP 约不高于 200ms、CLS 约不高于 0.1，通常按第 75 百分位判断。不要把单次本机 Lighthouse 分数当作真实用户结论。

### 测量纪律

- 记录 URL、构建类型、设备/节流、冷/热缓存、运行次数、工具版本和时间。
- 对波动指标多次运行并报告中位数或分布，避免挑选最好一次。
- 区分实验室数据、field/RUM、预算和估算；不要混为一个“性能分”。
- 先确定瓶颈与用户影响，再建议优化；保留分析、转化、UTM 和业务关键功能。

### LCP 与加载

- 识别真实 LCP 元素，检查服务端响应、资源发现、优先级、尺寸与压缩。
- 检查 hero 图片是否被 CSS background、客户端 JS 或懒加载延迟发现。
- 检查字体数量、字重、子集、preload、`font-display` 和 fallback 指标。
- 检查关键 CSS、阻塞脚本、第三方标签、重定向和串行请求链。
- 检查公开内容是否因不必要的 CSR/hydration 才出现。

### INP 与主线程

- 检查长任务、过度 hydration、昂贵渲染、同步存储、布局抖动和第三方脚本。
- 检查输入响应先反馈，再做非关键工作；大任务可切片、延后或移出主线程。
- 检查大列表、复杂表格、编辑器和图表的容量与虚拟化策略。
- 不要把 `useMemo`、`useCallback` 或 worker 当作无证据的通用修复。

### CLS 与稳定性

- 为图片、视频、embed、广告和 skeleton 预留准确空间。
- 检查字体交换、客户端插入、cookie banner、提示条和动画导致的位移。
- 动画优先 `transform` 与 `opacity`；避免 `transition: all`。

### 预算与交付

- 检查初始 JS/CSS、图片、字体和第三方脚本是否有项目化预算和回归门禁。
- 检查代码分割是否落在真实路由或功能边界，避免碎片化和请求瀑布。
- 检查缓存头、CDN、压缩、预连接和预加载是否基于真实依赖图。
- 给出预计收益时标明估算依据；无法量化时不要编数字。

## 6. SEO 与可发现性

只对需要被发现和索引的页面加重 SEO 权重。

- 检查主内容是否存在于可索引 HTML，而不是完全依赖客户端执行。
- 检查唯一且有意义的 title、description、canonical、language、robots 和 status code。
- 检查 sitemap、内部链接、分页、重定向、404/410 和重复内容策略。
- 检查 Open Graph、分享信息和结构化数据与页面真实内容一致。
- 检查 heading 与链接文案表达内容结构，不为 SEO 堆关键词。
- 检查图片 alt、宽高、现代格式和发现优先级。
- 检查登录墙、个性化和 A/B 实验不会意外隐藏或复制公开内容。
- 不把 Lighthouse SEO 满分等同于搜索表现保证。

## 7. 内容、国际化与主题

- 使用真实、具体且动作导向的文案；避免 lorem ipsum 和虚假紧迫感。
- 检查日期、数字、货币、复数、时区和排序使用 locale-aware API。
- 检查长文本、CJK、RTL 和翻译扩张；不要硬编码固定宽度假设。
- 检查暗色模式不是简单反色，状态色和焦点在两种主题都达标。
- 检查系统主题、用户选择和持久化不会造成 hydration 闪烁。
- 检查错误与空状态解释原因、后果和下一步，而不是只显示错误码。

## 8. 验证协议

交付运行时发现时至少说明：

```text
路由 / 任务
构建与环境
视口 / 缩放 / 主题
操作步骤
预期与实际
截图、DOM、console、network 或工具证据
复现稳定性
修复后验证步骤
```

状态变化结论必须保留操作前后两份可区分的 evidence；单份终态截图只能证明终态。对比度 evidence 必须包含计算输入、sRGB 相对亮度公式、alpha 合成假设、阈值和工具限制，并用同状态截图人工复核。自动检查未运行时标记为未覆盖，不得写成通过。

若无法访问认证状态、真实数据、读屏、RUM 或生产环境，将其列为明确的未验证项，不要推断为通过或失败。
