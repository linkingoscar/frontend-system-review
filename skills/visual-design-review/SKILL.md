# Visual Design Review

以任务、品牌和系统一致性为基准，不用个人偏好冒充缺陷。

## 建立基准

记录产品定位、目标用户、品牌关键词、参考界面、设计 token、支持视口和关键状态。没有设计稿时从现有产品中归纳最稳定的模式，并明确这是推断而非官方规范。

## 评审维度

1. 信息层级与视觉动线是否支持主要任务。
2. 字体、字号、行高、行宽、字重和数字排版是否形成稳定层级。
3. 色彩、对比、语义色和暗色模式是否一致且可访问。
4. spacing、grid、对齐、圆角、边框、阴影和密度是否由 token 驱动。
5. 按钮、输入、导航、表格、卡片、弹窗等组件及 hover/focus/disabled/error/loading 状态是否完整。
6. 桌面、平板、移动和长文本/国际化下构图是否重排，而非整体缩小。
7. 空、少量、大量、错误和权限受限数据是否保持层级与可操作性。
8. 动效是否解释因果、尊重 reduced motion，并避免布局跳动。

## 截图与差异纪律

固定 commit、浏览器、视口、数据、主题、字体和动画条件后再比较。对每个差异记录基线图、当前图、diff、变化比例和人工判定。时间、随机内容、光标、骨架屏和第三方内容应遮罩或稳定化。

像素差异不自动等于 finding；先判断是否破坏品牌规则、信息层级、可访问性或任务完成。审美建议放在 polish，不升级为 P1。

## 输出

按“任务受损 / 系统一致性 / 视觉打磨”分组。每条 finding 引用页面、视口、状态和截图，说明规则、影响、建议 token/组件级修复及复测方式。被总控调用时只返回可复核候选，不单独给最终上线结论。
