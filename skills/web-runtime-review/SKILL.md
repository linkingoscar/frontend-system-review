# Web Runtime Review

以真实任务完成和可重复操作证据为核心。单张终态截图不能证明状态转换，单次本机指标不能代表真实用户分布。

## 建立任务矩阵

为每条关键流程记录：入口、用户角色、前置数据、桌面/移动视口、初始/加载/空/成功/错误状态、关键交互、期望结果和恢复路径。优先生产构建；记录 URL、commit、构建模式、浏览器、视口、网络条件、运行次数和时间。

## 声明式流程

若安装了 `frontend-system-review`，使用其 `scripts/runtime_audit.cjs` 与 `runtime-manifest.schema.json` 描述 `scenarios[].steps[]`。优先用 role、label、test id 等用户可感知定位器，避免脆弱 CSS。

场景至少覆盖适用项：登录/会话失效、菜单和弹窗、表单校验、0/1/大量数据、A→B→A、失败与重试、撤销与恢复。敏感值使用环境变量引用，不写入 manifest 或报告。

每一步保存前后状态、截图、焦点/URL/结构摘要和差异。视觉差异仅是候选证据；动态时间、动画和随机内容需要遮罩或人工复核。

## 检查维度

- 核心任务是否可发现、可完成、可撤销并能从失败恢复。
- 状态变化是否有及时反馈，焦点、滚动、键盘和返回行为是否正确。
- 桌面与移动是否溢出、遮挡、跳动或丢失关键操作。
- console、page error、失败请求、HTTP 错误和第三方依赖是否影响任务。
- LCP/CLS/长任务等实验室信号是否可重复；INP 需要真实交互，field 结论需要 RUM。
- title、language、heading、canonical、索引策略和内容可发现性是否匹配页面意图。

## 输出

每条 finding 引用路由、视口、场景、步骤和 artifact，给出复现、影响、修复与验证。另附任务/状态覆盖矩阵、环境限制、未覆盖角色与数据规模。被总控调用时不单独宣布全系统上线结论。
